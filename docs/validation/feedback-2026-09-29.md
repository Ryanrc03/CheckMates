# Experience review follow-up — 2026-09-29

Source: *CheckMates 分账应用体验反馈报告 V1.0* (desktop Chrome walkthrough of checkmates-pi.vercel.app, rated 4/5, no P0/P1 defects). This branch addresses all five findings and the seven roadmap suggestions.

## Findings

| # | Finding (severity) | Change | Evidence |
| --- | --- | --- | --- |
| 01 | Items have no quantity (P2) | Each line has **Qty** (1–99) and a unit price; a `2 × $3.50 = $7.00` line total appears when Qty > 1. The line total is stored exactly and restored after refresh. Split cards and breakdowns show `× 2`. | `extras.test.ts`, `split-even.test.ts`, e2e "quantity multiplies the line…" |
| 02 | Tax and tip are absolute amounts only (P2) | Tax and added tip each have a `$ / %` toggle; quick tip buttons 10/15/18/20%. The rate is kept after confirming, so editing a price later recalculates them. | e2e reproduces the report exactly: 8.25% → $3.04, 18% → $6.64, total $46.58; Burger → $16.00 gives $47.91 |
| 03 | "Everyone" only selects, cannot undo (P3) | Everyone is a toggle (`aria-pressed`, ✓ when all friends are selected); tapping again clears the item. | `useBillStore.feedback.test.ts`, e2e checks both states |
| 04 | Friend count read as "3friendsat the table" (P3) | The live HTML already contained spaces but split them across separate text nodes, which some tools join. The count now renders as one string. | e2e `toHaveText("3 friends at the table")` |
| 05 | Step numbers look inconsistent after going back from results (P3) | Progress shows **done** steps with a ✓, the **current** step with a ring, and later steps muted. Done and reachable steps are buttons, so you can jump back (for example Result → Receipt). | e2e "progress shows done steps…" |

The review's reference split still reconciles exactly: Alice $24.14, Bob $12.77, Carol $9.67, total $46.58.

## Roadmap items

| Priority | Suggestion | Change |
| --- | --- | --- |
| P0 | Quantity field | See #01 |
| P0 | Percentage tax and 10/15/18/20% quick tip | See #02 |
| P0 | One-tap even split | **Split evenly** on the friends page goes straight to the result; the split page has a `By dish / Split evenly` switch. Leftover cents rotate across the subtotal, tax and tip pools, so shares differ by at most 1 cent. Assignments are kept if you switch back. |
| P1 | Everyone can be undone | See #03 |
| P1 | Share link / QR code | Result page: **Copy link**, native **Share…** where supported, and an on-device QR code (`uqr`, rendered as SVG). The link's `#share=` fragment carries only names and amounts; a validated read-only page opens it. |
| P2 | Currency symbols | Currency picker on the receipt: USD, EUR, GBP, CNY, CAD, AUD, HKD, SGD, INR, MXN, CHF. Formatting, summary text and share links follow it. Only two-decimal currencies are offered, so integer-cent math is unchanged. |
| P2 | Mobile verification | New 320×640 touch-emulated test walks every step, including percent mode, quantity, even split and the QR code. It asserts no horizontal overflow and that all visible controls are at least 44 px tall and 24 px wide. Existing 375 px and 1280 px checks still pass. |

## Verification

Run on Windows with Node 24.18.0, Playwright 1.58.2 and Chromium headless shell 1228 against `next dev`:

- `npm test`: 73 tests in 15 files pass (57 before this change).
- `npx tsc --noEmit`, `npm run lint`, `npm run build`: pass.
- Browser suite (`npm run test:e2e`): 41 of 41 pass, including the real-OCR and photo-adjustment specs and the new `tests/e2e/feedback.spec.ts` (5 tests).

Not covered: physical phones, Safari/Firefox, and OCR of quantity columns (quantities are entered manually). Negative or non-numeric input was already rejected with inline errors; the new Qty and % fields follow the same rules.
